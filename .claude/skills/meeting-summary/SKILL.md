# Meeting Summary

회의 내역을 **입력 확보 → (크면) 청크 map 요약 → 결합·액션아이템 판정 → 요약 산출 → (선택) 칸반/Notion 반영** 순서로 정리한다.
요약이 핵심이고, 칸반 승격·Notion 기재는 사용자가 원할 때만 하는 선택 단계다.

**이 스킬을 수행하는 동안 사용자에게 보내는 모든 응답·확인 질문·보고는 한글로 작성한다.** (요약도 한글)

## 0. 입력 확보

입력은 **회의 내역 문서**(전사문·회의 메모 텍스트)이거나 **오디오 파일**이다.

- **문서**(기본): 파일 경로나 붙여넣은 텍스트를 그대로 입력으로 쓴다.
- **오디오**: 이 스킬은 전사(STT)를 포함하지 않는다. 오디오만 주어지면
  **먼저 텍스트 전사가 필요하다**고 알리고, 전사문(사용자가 가진 STT 도구·서비스 결과)을 받아 이어간다.
  임의로 "전사했다" 하지 않는다.

입력이 없으면 먼저 무엇을 요약할지 묻는다. 산출물은 스크래치 폴더나 작업 폴더의 `summary.md` 로 쓴다.

## 1. 요약 — 크기로 갈린다

**전사문은 크다(1시간 ≈ 수백 발화). 통째로 메인 컨텍스트에 읽지 않는다.**

- **작은 문서**(수십 줄): 메인이 바로 읽고 아래 형식으로 요약한다.
- **큰 전사문**: 청크로 나눠 map/reduce 한다.
  1. **분할** — 내용을 읽지 않고 파일만 대략 균등하게 N조각으로 쪼갠다(대략 120발화/청크 → 보통 3~5).
     `split` 이나 짧은 스크립트로 `chunks/part_01.txt …` 를 만든다.
  2. **map(Sonnet)** — 청크 1개당 서브에이전트 1개를 `Agent`(subagent_type `claude`, **model `sonnet`**)로
     **병렬** 디스패치. 각 에이전트에 시킨다: "이 파일 하나만 Read 하고 아래 4묶음으로 부분요약을 반환하라 —
     ①결정 후보 ②액션/할 일 **언급**(누가·무엇을 — 원문 그대로. 할 일/완료 판정·담당 확정은 하지 말 것)
     ③미결/열린 질문 ④핵심 맥락. 없는 내용 창작 금지." 청크 파일 경로만 넘긴다.
  3. **reduce(Opus)** — 메인(또는 model `opus` 서브에이전트)이 부분요약만 모아(원문 아님) 중복 병합하고,
     액션/할 일 언급마다 담당·상태(할 일/완료)를 판정해 아래 형식으로 `summary.md` 를 쓴다.

### 요약 형식 (`summary.md`)

```markdown
# <회의 제목>
## 개요
- 참석자 / 날짜 / 길이 / 한 줄 주제
## 결정사항
1. <무엇을 정했나> — 근거 (누가)
## 액션아이템
- [담당자] <할 일> · 도메인: <도메인명> · 상태: 할 일 | 완료
## 미결·추후
1. <열린 질문 / 보류>
```

- 이미 끝났다고 보고된 일은 `상태: 완료`. 애매하면 `미결·추후` 로 내린다. 담당 미정은 `[미정]`.
- **결정사항·미결은 번호를 매긴다** — 액션아이템 근거가 "결정②"·"미결①" 로 이 항목을 가리킬 수 있게.
- 없는 수치·결정은 창작하지 말고 미결로 내린다.

## 2. 요약 산출 + 보고

`summary.md` 를 사용자에게 보여주고 멈춘다. 요약만 원했으면 여기서 끝. 다음 중 원하는 게 있으면 이어간다:

- **액션아이템을 칸반으로** → 3-A
- **Notion 회의록 DB에 기재** → 3-B

## 3-A. (선택) 액션아이템을 칸반 카드로

액션아이템을 태스크 묶음으로 정리해 [new-task](../new-task/SKILL.md) 절차로 칸반에 올린다.
`상태: 할 일` 은 시작 전 컬럼 신규 카드, `상태: 완료` 는 완료 카드(이력)로. new-task 가 예시 게이트로 확인받아 생성한다.
**요약만 본 단계에서 자동으로 카드를 만들지 않는다** — 사용자가 "칸반에 올려줘"라고 할 때만.

## 3-B. (선택) Notion 회의록 DB에 기재

`tools/notion/notion.py` 로 요약을 회의록 페이지로 남긴다(도구·`.env` 준비는 [tools/notion/README.md](../../../tools/notion/README.md)).

```
python notion.py create-meeting "<제목>" summary.md tasks.json [--date YYYY-MM-DD] [--people id1,...]
```

- `tasks.json` = `{"groups":[{title, owner, track, status, target, details:[...], basis?:{label,kind,idx}}, ...]}`.
  분리 태스크가 없으면 `{"groups": []}` 로 두면 요약만 기재된다.
- `basis`(근거)는 생성 후 결정/미결 블록 딥링크로 자동 승격된다.
- `NOTION_DB_ID`(회의록 DB)가 `.env` 에 없으면 막히니, 없으면 `python notion.py list-dbs` 로 찾아 넣도록 안내하고 멈춘다.

## 하지 않는 것
- 전사 원문을 메인 컨텍스트에 통째로 읽기 — 청크 → Sonnet 서브에이전트로 우회.
- 없는 결정·수치 창작 — 미결로 내림.
- 오디오를 "전사했다"고 임의 처리 — 전사문을 받아 이어간다.
- 요약만 요청받고 칸반·Notion 에 자동 반영 — 사용자가 원할 때만(3단계).
- git push / 커밋 — 사용자가 명시할 때만.
