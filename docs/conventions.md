# 규약 (conventions)

수직 도메인 DDD 프레임워크의 공통 규약. 스킬·에이전트가 이 문서를 공유 기준으로 삼는다.

## 위키 루트
- 위키 루트는 `docs/` 직접.
  - `docs/HOME.md` — 도메인 지도(목록 + 의존 그래프).
  - `docs/CONTEXT.md` — 용어·공유 개념.
  - `docs/domains/<name>.md` — 도메인당 1페이지(계약서 = 위키).
  - `docs/arch/ARCHITECTURE.md` — 전역 규약(dev-arch 산출).

## 도메인
- **수직 도메인** = 기능 단위. 프론트(씬)+백(데이터)을 세로로 관통.
- 씬/데이터는 도메인 *안*의 레이어이지 최상위 분할 축이 아니다.
- slug는 영문 kebab/소문자. 표시 이름은 한국어 허용.
- 도메인 간 의존은 **단방향·비순환**. 의존은 `docs/HOME.md` 그래프 + 도메인 페이지 `의존` 절에 기록.

## 도메인 페이지 (`docs/domains/<name>.md`)
- 템플릿: `templates/도메인.md`.
- 고정 절: 역할 / 구현목표·수용기준 / 경계(하지 말 것) / 의존 / 패턴(TS·DM) / 상태 / 일지.
- 선택 절: 씬(플로우·V) / 데이터(M·C) — 디테일이 있을 때만.
- 프런트매터: `domain`·`status`·`pattern`·`depends` (+ implement.ps1 백엔드용 `branch`·`base`·`engine`).

## 값 생성 금지
- AI는 수치·수량·비율·규칙·계산식·enum 값 의미를 **짓지 않는다**.
- 빠진 값은 `*[입력 필요: …]*` 슬롯으로 비운다. AI가 짓는 건 ① 뼈대 문장 ② 슬롯 ③ 질문.
- 빈 슬롯이 남은 도메인은 ddd-build/implement.ps1에서 막고 사람에게 돌린다.

## 일지 하네스
- 도메인 페이지를 편집하기 전 그 `일지` 절을 읽고, 의미 있는 변경 후 항목 1개 추가 + `상태` 절 갱신.
- 오타·링크 정리 같은 무가치 변경은 제외.

## 패턴 정책 (TS/DM)
- 도메인별 기본값을 `docs/arch/ARCHITECTURE.md` §패턴 정책에서 정한다.
  - **TS(트랜잭션 스크립트)** — 단순 CRUD·절차적, 규칙이 얇을 때.
  - **DM(도메인 모델)** — 규칙·불변식·상태가 풍부할 때.
- 도메인 페이지 `패턴` 절에 채택값 + 근거. 기본값과 어긋나면 갈림길로 올려 묻는다.

## 명명·언어
- 코드·식별자: 영문. 주석·문서: 한국어.
- 명명·직렬화 컨벤션은 ARCHITECTURE를 따른다.

## 구현 경계
- 서브에이전트(`ddd-domain-impl`)·구현 엔진은 도메인 페이지 계약서대로만 구현.
- `경계(하지 말 것)` 밖 파일 수정·재설계·리네이밍·겸사겸사 리팩터·새 의존 추가 금지. 의존 도메인은 읽기만.
- 모호하거나 빈 슬롯이면 멈추고 보고. push는 사람이.
