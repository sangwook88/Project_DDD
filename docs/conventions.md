# 규약 (conventions)

FE/BE 2분할 DDD 프레임워크의 공통 규약. 스킬·에이전트가 이 문서를 공유 기준으로 삼는다.

## 분할 축 (핵심)
- **최상위 분할 = FE vs BE.** 한 도메인이 둘을 다 짊어지지 않는다(수직 도메인 금지 — 기능이 쌓이면 비대해진다).
- **FE 도메인** = 플로우(오케스트레이션) + 표현(V)만. 기능 구현 로직 금지.
- **BE 도메인** = 데이터(M) + 기능(C)만. 플로우 순서·화면·연출 금지.
- **참조는 단방향: FE → BE.** FE 요소가 BE 기능을 **링크로만** 부른다. BE는 FE를 모른다. BE 도메인 간 의존도 단방향·비순환.
- 기능 추가 = 폴더에 **파일 추가**(FE는 `요소/<노드>.md`, BE는 `기능_<name>.md`)이지 한 문서를 부풀리는 게 아니다.

## 위키 루트
- 위키 루트는 `docs/` 직접.
  - `docs/HOME.md` — 도메인 지도(FE/BE 목록 + FE→BE 참조 그래프).
  - `docs/CONTEXT.md` — 용어·공유 개념.
  - `docs/fe/<name>/` — FE 도메인 폴더.
  - `docs/be/<name>/` — BE 도메인 폴더.
  - `docs/arch/ARCHITECTURE.md` — 전역 규약 + 기술 스택(arch 산출).
  - `docs/brainstorming/` — brainstorm 설계 브리프.

## FE 도메인 (`docs/fe/<name>/`)
- 표준 구조: `README.md`(도메인폴더-README 템플릿) + `플로우.md`(루트 고정·단일, mermaid + FE 전체 값) + `요소/<노드>.md`(노드 1 = 파일 1, 요소 템플릿) + `일지.md`.
- 요소 §호출하는 기능 = BE 도메인 기능 **링크만**. 구현 로직 금지.
- 금지: 플로우를 단계폴더(C/·M/·V/)에 두기, 노드 상세를 `요소/` 밖에 흩뿌리기.

## BE 도메인 (`docs/be/<name>/`)
- 표준 구조(평평): `README.md` + `데이터.md`(M, 소유 테이블/enum 한 파일) + `기능_<name>.md`(C, 기능당 1파일) + `일지.md`.
- 공유 데이터는 `데이터.md`에 한 번만, 기능은 링크 참조. 기능 문서는 "무슨 데이터를 읽고 어떻게 처리하나"만(언제 부르나는 FE가 정함).

## 값 생성 금지
- AI는 수치·수량·비율·규칙·계산식·enum 값 의미를 **짓지 않는다**.
- 빠진 값은 `*[입력 필요: …]*` 슬롯으로 비운다. AI가 짓는 건 ① 뼈대 문장 ② 슬롯 ③ 질문.
- 빈 슬롯이 남은 도메인은 build/desk/implement.ps1에서 막고(기획 트랙=plan으로) 사람에게 돌린다.

## 일지 하네스 (쓰기 전용)
- `일지.md`는 **쓰기만 하고 읽지 않는다** — 디버깅용 결정 로그다. 쌓인 이력을 매번 읽으면 토큰만 늘고 환각을 부른다(필요할 때 사람이 본다).
- 의미 있는 변경(데이터 구조·규칙·스키마·enum·관계·플로우·시점 등 "이렇게 하기로 했다") 후 `일지.md`에 항목 1개 추가 + `현재 상태 요약` 갱신.
- 오타·링크 정리 같은 무가치 변경은 제외.

## 패턴 정책 (TS/DM)
- **BE 도메인**에만 적용(기능 C의 로직 패턴). FE는 플로우+V라 해당 없음.
- 도메인별 기본값을 `docs/arch/ARCHITECTURE.md` §패턴 정책에서 정한다 — **기획 QA 후 `arch` 단계**에서 기술 스택과 함께 결정.
  - **TS(트랜잭션 스크립트)** — 단순 CRUD·절차적, 규칙이 얇을 때.
  - **DM(도메인 모델)** — 규칙·불변식·상태가 풍부할 때.
- BE 도메인 `README.md`에 채택값 + 근거. 기본값과 어긋나면 갈림길로 올려 묻는다.

## 명명·언어
- 코드·식별자: 영문. 주석·문서: 한국어. 도메인 slug 영문(`fe/`/`be/` 트랙), 요소·기능 파일명 한국어 허용.
- 명명·직렬화 컨벤션은 ARCHITECTURE를 따른다.

## 구현 경계
- 구현 에이전트(`dev`)·구현 엔진은 배정된 **도메인 폴더(또는 티켓)만** 계약서대로 구현. 계약이 FE/BE를 선언하므로 트랙별 에이전트를 가르지 않는다(구현 에이전트는 한 종류). 오케스트레이터(`desk`)가 도메인을 분류·디스패치한다.
- 경계 밖 파일 수정·재설계·리네이밍·겸사겸사 리팩터·새 의존 추가 금지. 참조 도메인(FE→BE, BE→BE)은 읽기만.
- 모호하거나 빈 슬롯이면 멈추고 보고. push는 사람이.

## 변경 접수 (raw → intake)
- 운영 중 들어오는 회의록·신규 기획·리팩토링 문서는 `raw/*.md` 인박스에 떨군다. `intake` 스킬이 스캔하고, 문서 1개당 git 브랜치(worktree)에서 `intake` 에이전트를 1개씩 돌린다.
- `intake` 에이전트는 문서를 3트랙으로 가른다: ① **새 도메인 경계** 필요 → 멈추고 사람에게 `decompose` 반환(경계는 사람 게이트, AI가 경계를 짓지 않는다). ② **기존 도메인 기획 수정** → `plan`이 문서 수정(+FE 플로우가 바뀌면 `qa`가 HTML 재생성) + `dev`가 티켓만 발행하고 멈춤(사람이 티켓·QA 검수) → 재트리거 시 `dev`가 구현(2단계 정지). ③ **작은 구현 수정**(계약 불변) → `dev`가 티켓 발급 + 바로 구현.
- 모든 intake 작업은 배정 브랜치에 **로컬 커밋만** — push·merge·PR은 사람. 처리된 문서는 `raw/_done/`로 옮겨 중복 접수를 막는다.

## 단계별 에이전트 분담
- 기획 전단 단계는 메인 스레드 스킬로 직접 부르거나 서브에이전트로 돌릴 수 있다. brainstorm(아이디어 다듬기)만 사람과 대화로 남고, 나머지는 전부 에이전트 처리된다.
- `plan` — decompose·plan-fe·plan-be·**distill**·arch (도메인 골격 작성 + 가지치기·정제).
- `qa` — 기획 QA. FE 도메인 HTML(`_qa/<fe>.html`) + 7렌즈 누락 초안 **생성** → 사람 클릭·피드백 → 확정 누락을 문서에 **in-place 융합**(2단계). 직접 플레이하지 않고 HTML만 만든다.
- `dev` — 구현. **ticket 발행 모드**면 자기완결 티켓만 쓰고 멈춘다(검수 게이트), 구현 모드면 계약대로 구현.
- `desk` — 구현 오케스트레이터(분류·wave·디스패치). `intake` — raw 문서 접수·라우팅.
