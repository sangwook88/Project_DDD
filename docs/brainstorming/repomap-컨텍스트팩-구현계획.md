# repomap식 컨텍스트 팩 — 구현 계획서

> DDD LLM-wiki를 Aider repo-map처럼: 타깃 도메인에 바로 도달해 관련 계약·코드 골격을
> 거리 티어로 압축, LLM 디스패치 직전 자동 주입한다. (착수 2026-06-29)

관련 문서: [리서치 메모](repomap-context-pack-리서치.md) · 규약 `docs/conventions.md` §인터페이스(계약면)

---

## 1. 목표 · 성공 기준

**목표:** dev/plan 에이전트가 작업 전, "타깃 도메인 전문 + 이웃 계약 + 타깃 코드 골격"을
한 장으로 자동으로 받아 — 기존 코드를 알고 정확히 수정하며, 경계 밖을 안 건드린다.

**성공 기준 (측정 가능):**
- [ ] 임의 타깃 1개에 대해 `context-pack`이 0.5초 내·토큰 0으로 팩 1장 생성
- [ ] 팩에 ①타깃 전문(T0) ②이웃 계약면(T1) ③타깃 코드 시그니처 골격(Tier B)이 포함
- [ ] 도메인 간 엣지가 어긋나면 `home-check`가 exit 1로 게이트 차단
- [ ] 코드만 바뀐 변경은 골격에 자동 반영(재선언 0), 도메인 간 변경만 게이트에 노출
- [ ] desk가 ad-hoc 파일 읽기 대신 `context-pack` 호출로 디스패치

## 2. 아키텍처 (확정)

```
티켓 → desk → (HOME 그래프 BFS로 스코프) → context-pack → LLM → dev
                                              │
           ┌──────────────────────────────────┴───────────────────┐
   Tier A 도메인 간 (선언)                    Tier B 도메인 안 코드 (파생)
   HOME ## 참조 그래프                         README code: → tree-sitter
   T0 전문 / T1 계약면 / T2 한줄               시그니처 골격(본문 ⋮…), 캐시
   진실=커밋 md, home-check 검증               진실=코드, .ddd-cache 일회용
```

**불변 원칙 (되돌리지 말 것):**
- 도메인 간 참조 = **선언**(`depends:`/요소 링크 → HOME), home-check가 검증
- 도메인 안 참조 = **파생**(tree-sitter), 아무 데도 선언 안 함
- 코드 구조는 **md에 절대 안 적음**
- Tier B = **순수 시그니처 골격**, docstring 레이어 없음(검토 후 기각) — 의도는 위키 계약이 담당
- PageRank 불필요 — 엣지가 선언돼 거리가 정확(BFS로 충분)
