# ddd-build — 도메인 구현 오케스트레이션 (3단계)

명세된 도메인들을 의존 순서대로 묶어 **도메인별 서브에이전트**로 구현시킨다. 전제: [ddd-spec](../ddd-spec/SKILL.md)으로 도메인 페이지 명세 + 사람이 슬롯 채움. 규약 SoT: `docs/arch/ARCHITECTURE.md`.

## 시작 전 읽기
1. `docs/HOME.md` — 도메인 목록 + 의존 그래프.
2. `docs/domains/*.md` — 각 도메인 페이지(상태·의존·`[입력 필요]` 잔존 여부).
3. `docs/arch/ARCHITECTURE.md` — 전역 규약.

## 1. 준비 점검 (게이트)
- **빈 슬롯 차단** — `[입력 필요]` 슬롯이 남은 도메인은 구현 대상에서 빼고 사람에게 돌린다(채운 뒤 재실행).
- **의존 그래프 검증** — HOME의 의존이 단방향·비순환인지 확인. 순환이면 멈추고 ddd-decompose로 경계 재검토 안내.

## 2. wave 편성
의존 그래프로 위상 정렬해 **독립 도메인을 같은 wave로** 묶는다:
- wave 1 = 의존 없는(또는 이미 done인 도메인에만 의존하는) 도메인들.
- 이후 각 wave = 직전 wave까지 done이면 풀리는 도메인들.
- wave 안의 도메인끼리는 서로 독립 → 병렬 가능.

## 3. 백엔드 선택 (서브에이전트 띄우기 직전, 1회)
**구현을 시작하기 직전에 사람에게 묻는다:**
```
구현 백엔드를 고르세요:
- A) 세션 내 Agent 병렬 — 이 세션에서 도메인별 서브에이전트를 동시에 띄워 구현.
- B) implement.ps1 — 도메인당 브랜치를 따고 codex/claude 헤드리스로 구현(검토·커밋은 사람).
```
선택대로 4를 진행한다. (도메인별로 다르게 가고 싶다는 요청이 있으면 도메인 단위로 물어도 된다.)

## 4. wave별 구현
wave 순서로, wave 안은 병렬:

### A) 세션 내 Agent 병렬
- wave 내 각 도메인마다 `Agent`(subagent_type: `ddd-domain-impl`)를 띄운다. 한 메시지에서 독립 도메인들을 동시에 디스패치.
- 프롬프트에 그 도메인 페이지 경로(`docs/domains/<name>.md`)와 "규약 SoT = docs/arch/ARCHITECTURE.md"를 명시. 서브에이전트는 페이지를 계약서로 구현만 한다(경계 엄수, 모호·빈슬롯이면 멈추고 보고).

### B) implement.ps1
- wave 내 각 도메인마다 다음을 안내(스킬이 직접 실행하지 않는다 — 검수 게이트 보존):
  ```
  pwsh scripts/implement.ps1 -Domain docs/domains/<name>.md
  ```
  `branch`/`base`/`engine`은 도메인 페이지 프런트매터에서 읽는다. 검토·커밋·push는 사람.

## 5. wave 마감
- 도메인 구현이 끝나면 그 페이지 `상태: done` + `일지`에 결정 1줄 갱신, HOME 표 상태도 갱신.
- 다음 wave로. 막힌(보고하고 멈춘) 도메인은 사람에게 돌리고 그 의존 후속은 보류.

## 종료
완료/미완/보류 도메인 요약. 미완이 있으면 막힌 이유 1줄씩. 한국어 + 마크다운, 식별자 영문.
