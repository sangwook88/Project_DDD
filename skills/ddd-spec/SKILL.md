# ddd-spec — 도메인별 명세 (2단계)

`docs/HOME.md`의 **모든** 도메인을 도메인당 1페이지 계약서로 명세한다. **구현은 시작하지 않는다.** 전제: [ddd-decompose](../ddd-decompose/SKILL.md)로 HOME 확정. 규약: [docs/conventions.md](../../docs/conventions.md). 템플릿: [templates/도메인.md](../../templates/도메인.md). 산출: `docs/domains/<name>.md`.

## 절대 규칙
1. **AI는 값을 생성하지 않는다.** 수치·규칙·계산식·enum 값 의미를 짓지 않는다. 빠지면 `*[입력 필요: …]*`. AI가 짓는 건 ① 뼈대 문장 ② 슬롯 ③ 질문.
2. **모든 도메인 먼저.** 구현 전에 HOME의 도메인을 빠짐없이 페이지화("다 만들어두고").
3. **일지 하네스.** 도메인 페이지를 의미 있게 바꾸면 그 페이지 `일지` 절에 항목 1개 + `상태` 갱신.
4. **한 번에 한 갈림길.**

## 시작 전 읽기
1. `docs/HOME.md` — 도메인 목록·의존 그래프(없으면 ddd-decompose 먼저).
2. `docs/arch/ARCHITECTURE.md` §패턴 정책 — 도메인별 TS/DM 기본값.
3. `docs/CONTEXT.md` — 용어.
4. 기존 `docs/domains/*.md` — 이미 명세된 것(중복 방지).

## 흐름
도메인을 **한 페이지씩 순차**로:
1. **페이지 생성** — `templates/도메인.md`를 복제해 `docs/domains/<slug>.md`로. 프런트매터(`domain`/`status`/`pattern`/`depends`) 채움. implement.ps1 백엔드를 쓸 도메인이면 `branch`/`base`/`engine`도.
2. **역할·경계·의존 골격** — HOME 역할·의존을 페이지로 옮겨 적되, 구체 책임/하지말것은 슬롯+질문으로.
3. **구현목표/수용기준** — 결과문 형태(`<조건>이면 <결과>`)의 뼈대. 값은 슬롯.
4. **패턴(TS/DM)** — ARCHITECTURE 정책 기본값에서 출발. 기능 성격이 맞으면 그대로 + *왜* 한 줄. 어긋나면 갈림길로 제안:
   ```
   구조 갈림길: <무엇을 어떻게 담을까>
   - A) TS(기본값 계승) — 트레이드오프
   - B) DM             — 트레이드오프
   추천: X. 왜: …
   ```
5. **선택 절** — 프론트/백 디테일이 있으면 `씬(플로우·V)`/`데이터(M·C)` 절을 연다. 없으면 비운다(주석 유지).

## 종료
- 생성된 도메인 페이지 목록 + 남은 `[입력 필요]` 슬롯 요약 + "사람이 슬롯 채우기" 안내.
- "다음 = [ddd-build](../ddd-build/SKILL.md)로 구현 (빈 슬롯 채운 뒤)" 안내.
- 한국어 + 마크다운, 식별자 영문.
