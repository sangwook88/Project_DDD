# ddd-decompose — 도메인 분할 확정 (1단계)

기능을 **기능별 수직 도메인**으로 가른다. 각 도메인은 프론트(씬)+백(데이터)을 세로로 관통하는 한 덩어리. AI가 제안하고 **사람이 확정**한다. 규약: [docs/conventions.md](../../docs/conventions.md). 산출: `docs/HOME.md`.

## 절대 규칙
1. **값 생성 금지.** 수치·규칙·계산식을 짓지 않는다. 도메인 *경계와 책임*만 가른다.
2. **한 번에 한 갈림길.** 도메인 하나씩 제안 → 확정.
3. **수직 경계.** 도메인 = "이 데이터·규칙·화면을 한 책임으로 묶을 수 있는 기능 단위". 씬/데이터로 먼저 가르지 않는다(그건 도메인 *안*의 레이어).

## 시작 전 읽기
1. `docs/HOME.md` — 기존 도메인 지형(있으면). 없으면 새로 만든다.
2. `docs/CONTEXT.md` — 용어·공유 개념(있으면).
3. 코드 현황(가볍게) — 기존 디렉토리·모듈로 이미 선 그어진 경계 파악.

## 흐름
1. **입력 수집** — 브레인스토밍 산출/아이디어/문서 경로. 비었으면 "무엇을 만들고 싶으신가요".
2. **맥락 살짝** — HOME·CONTEXT로 기존 도메인·용어, 중복·소속 판단.
3. **분할 초안 제안 + 확정** — 기능을 수직 도메인 후보로 가른 초안을 보여주고 **하나씩** 확인:
   - 각 후보: 잠정 slug(영문) · 한 줄 역할 · 신규 vs 기존 확장.
   - 경계가 애매하거나 한 기능이 둘에 걸치면 갈림길로 올려 묻는다(임의로 가르지 않는다).
4. **의존 짚기** — 확정 도메인 간 의존(읽기/호출/구독)과 방향을 단방향으로 정리. 순환이 보이면 경계 재검토.
5. **중복·충돌 점검** — 기존 도메인과 책임이 겹치면 흡수/분리 중 사람이 결정.

## 산출 — docs/HOME.md
도메인 지도를 갱신(없으면 생성):
```markdown
# 도메인 지도

## 도메인
| slug | 역할(한 줄) | 상태 |
|---|---|---|
| <slug> | … | not-started |

## 의존 그래프
- <slug-A> → <slug-B>   # A가 B를 읽기/호출/구독 (단방향)
```
- 표의 `slug`는 영문, 역할은 한국어 한 줄.
- 의존 그래프는 다음 단계(ddd-build)에서 wave 순서의 근거가 된다.

## 종료
확정 도메인 수 + 의존 요약 + "다음 = [ddd-spec](../ddd-spec/SKILL.md)으로 도메인별 페이지 명세" 안내. 한국어 + 마크다운, 식별자 영문.
