# qa — HTML 기획 QA (기획 전단 5단계)

FE 기획 검증의 **독립·재사용 기능 3종**. 전제: [distill](../distill/SKILL.md) 완료. 규약: [docs/conventions.md](${DDD_ROOT}/docs/conventions.md). 입력 = FE 도메인 1개(`docs/fe/<name>/`) + 그것이 부르는 BE 기능(`docs/be/*/기능_*.md`).

## 하드 제약 (공통)
1. AI는 값(수치·규칙·방식)을 생성하지 않는다 — "이 경우가 빠졌다"만 찾고, 해소값은 `*[입력 필요: …]*`. HTML 예시 데이터는 `[예시]`로 명시.
2. 기획 문서(`docs/fe/*/`·`docs/be/*/`)만 건드린다(구현 코드 금지).
3. 누락 분기는 기존 문장에 in-place 융합(뒤에 덧붙이기 금지).

## 기능 1 — 요소별 호출 매핑
**입력:** FE `요소/<노드>.md` + 그것이 가리키는 BE `기능_*.md`/`데이터.md`.
각 요소(7섹션)와 호출 기능을 표로(이 표 = 기능 2의 시뮬 대본):

| 순서 | 노드(요소) | 입력값 | 호출 BE·기능 | 분기 | 출력값 |
|---|---|---|---|---|---|

## 기능 2 — 단일 HTML 아티팩트 생성 (에이전트 직접 플레이 대체)
**입력:** 기능 1 매핑표 + FE `플로우.md` 진입-상태 계약 + 관련 `데이터.md`.
[templates/sim.html](../../templates/sim.html)를 복사해 `_qa/<fe>.html` 생성:
- 매핑표를 **노드 순서대로** `.step` 블록으로 — 각 노드 `진입상태(예시) → 호출기능 → 출력상태`.
- 분기/선택지마다 **버튼**(`go('<다음노드>')`). 문서에 없는 전이는 버튼이 "누락 후보" 경고(그린 대로만, 없는 동작 생성 금지).
- 예시 데이터 = `[예시]`, 미정 값 = `[입력 필요]`로 그대로 노출.
- **하단 2패널**(`textarea`)에 **7렌즈**로 누락 초안: 경계·빈값 / 분기 누락 / 입력 계약 위반 / 순서·동시성 / 상태 전이 충돌 / 실패 경로 / 루프 종료. 패널① `FE 플로우에서 놓친 부분`, 패널② `BE 처리에서 미고려 기능`.
- **이 기능은 HTML만 만든다(문서 안 고침).** 사람이 클릭하며 패널을 확정·보강한다.

## 기능 3 — in-place 융합
**입력:** 대상 문서 1개(FE `요소/*.md` 또는 BE `기능_*.md`) + 확정된 누락 목록(노드·빠진 섹션·분기·예외).
대상 문서의 기존 문장에 누락 분기·예외를 **절로 녹인다**:
- 보통 FE 요소 `분기·다음 전이`/`예외·실패 처리`, BE 기능 `예외·경계`를 보강(끝에 새 섹션 금지).
- AI가 짓는 건 "이 경우가 존재하고 처리가 필요하다"는 뼈대 분기 문장뿐. 해소값은 `*[입력 필요: …]*`.
- 일지 하네스(편집 전 도메인 폴더 `일지.md` 읽기, 의미 있는 변경 후 항목 + 상태 갱신).
산출: 무엇을 어디 녹였는지 + 남은 `[입력 필요]` 슬롯 목록.

## 오케스트레이션 / 종료
FE 여러 개면 한 도메인씩 순차(기능1→2→사람 클릭→3). 값 결정·채우기는 사람·[plan-fe](../plan-fe/SKILL.md)/[plan-be](../plan-be/SKILL.md). 통과하면 "다음 = [arch](../arch/SKILL.md)로 기술·구조 결정" 안내.
