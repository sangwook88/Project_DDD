# distill — 가지치기·정제 (기획 전단 4단계)

plan-be/fe가 끌어낸 도메인 문서를 *가지치기*해 핵심 완결 문장만 남기고 애매한 표현을 정제한다([slim-agent](https://gist.github.com/lsc892/6a0f63f565162fcf266f775643439ca9)를 도메인 문서에 적용). 입력 단위 = 문서 한 개(FE `요소/<노드>.md` / BE `기능_<name>.md`·`데이터.md`). 전제: [plan-fe](../plan-fe/SKILL.md)/[plan-be](../plan-be/SKILL.md)가 구체값까지 캐물어 채움 + 사람이 슬롯 채움. 규약: [docs/conventions.md](${DDD_ROOT}/docs/conventions.md).

> 군더더기: "이 기능은 사용자의 요청을 받아 처리한 다음 그 결과를 적절히 가공해 반환하는 역할을 담당한다."
> 가지치기: "요청에 `userId·기간`이 오면 그 기간의 주문을 조회해 `[입력 필요: 정렬 기준]`으로 정렬해 반환한다."

## 원칙 (slim-agent)
삭제가 아니라 "처음부터 이렇게 쓴 듯" 다시 쓰기 — 핵심 의도(트리거·대상·동작·값)를 표현할 때 자연히 나올 문장만 남긴다. 의도 보존이 토큰 절감보다 우선, 애매하면 남긴다.

## 분류 (문서를 읽고)
- **핵심** — 동작/효과(트리거·입력·대상·수량·규칙·결과·분기) / 데이터·속성(정의·값·범위·단위·enum 의미·관계): 표현만 압축, 의미 그대로.
- **군더더기** — 자명한 수식·반복·메타설명: 제거("지우면 동작이 바뀌나?" 아니면 버린다).
- **결정이력** — "왜 바꿨나"·대안 비교: 본문 금지 → 일지로 이송.
- **중복** — 흩어진 같은 규칙: 부모 규칙 하나로 통합.

## 하드 제약 (신성불가침)
1. AI는 값을 생성하지 않는다 — 빈 슬롯 `*[입력 필요: …]*`은 그대로 두고 '미충족'으로 표시.
2. 사용자에게 캐묻지 않는다 — 값 끌어내기·추상 문장 구체화는 plan-be/fe 몫. distill은 이미 있는 글만 가지치기·정제.
3. 핵심 의미(트리거·대상·동작·값)는 어떤 압축에도 살아남는다.
4. 이미 군더더기 없는 완결 문장은 안 건드린다.

## 흐름
1. 대상 문서를 읽는다. 용어 통일은 `CONTEXT.md` 가볍게 참고. (`일지.md`는 읽지 않는다 — write-only.)
2. 엔트리를 핵심/군더더기/결정이력/중복으로 분류 → **가지치기 계획표** 출력(무엇을 자르고 무엇을 통합·정제하나).
3. 확인받은 뒤 본문 덮어쓰기: 군더더기 제거 · 중복 통합 · 애매한 문장을 핵심 완결 문장으로 정제 · 결정이력은 일지로.
4. 핵심 의미 보존 검증(트리거·대상·동작·값이 살아남았나) → 남은 빈 슬롯 '미충족' 목록 정리.

## 산출
가지친 본문(핵심 완결 문장 + 잔여 `[입력 필요]`) 즉시 덮어쓰기. 결정이력은 그 도메인 폴더 `일지.md`로. 의미 있는 변경 후 `현재 상태 요약` 갱신. 한국어 + 마크다운, 식별자 영문.

## 종료
가지친 페이지 + '미충족' 슬롯 요약 + "빈 슬롯 남으면 [plan-fe](../plan-fe/SKILL.md)/[plan-be](../plan-be/SKILL.md)로 되돌려 채운 뒤, 다음 = [qa](../qa/SKILL.md)로 HTML 기획 QA" 안내.
