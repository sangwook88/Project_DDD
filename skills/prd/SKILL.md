# prd — 외부 공개용 PRD 저작

흩어진 기획 산출물(브리프·로드맵·HOME·ARCHITECTURE)을 **하나의 외부 조망 문서**로 종합한다. 대상 독자 = 팀 외부(비개발자 포함) — 맥락 없이 읽어도 "무엇을 / 왜 / 누구를 위해"가 통해야 한다. 내부 구현 상세·티켓 명세는 [ticket](../ticket/SKILL.md) 몫이라 여기선 **제품 가치로 번역**만 한다. 전제: 최소 브리프+로드맵(HOME·ARCHITECTURE 있으면 풍부해짐). 규약: [docs/conventions.md](${DDD_ROOT}/docs/conventions.md). 산출: `docs/PRD.md`.

## 이 스킬이 답하는 것
- **무엇을** — 제품 한 줄 요약 + 해결하는 문제.
- **누구를 위해** — 타깃 사용자·페르소나.
- **왜 이게 좋은가** — 핵심 가치·차별점.
- **뭐가 되나 / 안 되나** — 주요 기능(범위 In/Out).
- **어디로 가나** — 로드맵 요약(v1→vN) + 성공 지표(있으면).

## 절대 규칙
1. **AI는 값을 짓지 않는다.** 근거 문서에 없는 수치·페르소나·지표·차별점을 상상하지 않는다 — 빈 곳은 `*[입력 필요: …]*` 슬롯으로 남겨 사람이 채운다(규약 계승).
2. **근거에 접지.** 모든 문장은 브리프·로드맵·HOME·ARCHITECTURE의 실제 내용에서만 끌어온다. 근거 없는 주장(시장 규모·경쟁 우위 등)은 리서치 노트에 출처가 있을 때만, 없으면 슬롯.
3. **외부 언어로 번역.** 내부 도메인명·패턴(TS/DM)·모듈 경계·기술 스택 세부를 그대로 노출하지 않는다 — "무엇을 할 수 있는가"의 사용자 가치로 바꾼다(예: `be/payment 도메인` → "결제"). 스택은 필요할 때만 한 줄로.
4. **읽기 전용 위키.** 근거 문서·코드는 읽어 접지만, 쓰는 건 `docs/PRD.md` 하나뿐. 원본 기획 문서를 고치지 않는다.
5. **범위 = 현재 타깃 버전 중심.** "주요 기능(In)"은 로드맵의 현재 타깃 버전 포함 기능을, "Out/다음"은 이후 버전·YAGNI를 근거로 적는다.

## 시작 전 읽기
1. `docs/brainstorming/*-brief.md` — **거시 목표**(문제·가치·대상·핵심 기능)의 1차 소스. 없으면 "무엇을 만드는 제품인지" 최소 근거가 없으니 [brainstorm](../brainstorm/SKILL.md) 먼저 안내.
2. `docs/roadmap.md` — 버전 스코프 표 + **현재 타깃 버전** → 주요 기능 In/Out·로드맵 요약의 근거.
3. `docs/HOME.md` — 도메인 지도 → 실제 구현 범위를 기능 가치로 번역할 재료(도메인명은 그대로 쓰지 않음).
4. `docs/brainstorming/*-research.md`(있으면) — 시장·경쟁 근거 → 차별점·성공 지표의 **출처 달린** 뒷받침.
5. `docs/arch/ARCHITECTURE.md`(있으면) — 스택 한 줄 요약이 필요할 때만 참고.
6. `docs/PRD.md` — 이미 있으면 *갱신*(근거 문서 변화분 반영). 없으면 새로 만든다.

## 흐름
1. **근거 수집** — 위 문서를 읽어 목차별 재료를 모은다. 브리프가 없으면 멈추고 brainstorm으로 되돌린다.
2. **번역 초안** — 각 목차 칸을 근거→외부 언어로 채운 초안을 만든다. 근거가 없는 칸은 짓지 말고 `[입력 필요]` 슬롯.
3. **슬롯·모순 점검** — 비었거나(성공 지표가 흔함) 문서 간 어긋나는 곳을 목록으로 사람에게 확인.
4. **PRD 작성** — 확인 뒤 `docs/PRD.md`를 덮어쓴다. 남은 슬롯은 그대로 둔다(거짓보다 빈칸).

## 산출 — docs/PRD.md
외부 공개용 한 장. 고정 목차, 제품 가치 중심 톤:

```markdown
# <제품명> — PRD

> <제품 한 줄 요약: 누구의 어떤 문제를, 어떻게 해결하는 제품인가>

## 해결하는 문제
- <외부 독자가 공감할 문제 서술 — 내부 용어 없이>

## 타깃 사용자 · 페르소나
- **주 사용자**: <누구> — <상황·니즈>
- **페르소나**: *[입력 필요: 대표 사용자 상]* (근거 없으면 슬롯)

## 핵심 가치 · 차별점
- **핵심 가치**: <이 제품이 주는 가치>
- **차별점**: <기존 대안 대비 — 리서치 근거 있으면 출처, 없으면 슬롯>

## 주요 기능
**범위 In (현재 타깃 버전 <vN>)**
- <기능 A — 사용자 가치로 서술>

**범위 Out (지금 안 함 / 다음)**
- <기능 B> — 다음 버전 또는 YAGNI 사유

## 성공 지표
- *[입력 필요: 측정 지표]* (로드맵/브리프에 없으면 슬롯 — 짓지 않는다)

## 로드맵 요약
| 버전 | 목표(가치) | 핵심 |
|---|---|---|
| v1 (현재) | <한 줄> | <기능> |
| v2… | <한 줄> | <기능> |
```

- 산출 위치는 위키 루트 직접 `docs/PRD.md`(단일 조망 문서, roadmap.md와 같은 층).
- 제품명·설명은 한국어, 식별자·버전 라벨은 영문/원표기.
- 내부 도메인명을 노출하지 않는다 — 로드맵/HOME의 기능을 사용자 가치 문장으로 바꿔 적는다.

## 종료
작성한 `docs/PRD.md` 경로 + 남은 `[입력 필요]` 슬롯 목록(특히 성공 지표·페르소나·차별점 근거) 요약을 제시하고, "슬롯을 채우려면 brainstorm/roadmap으로 되돌리거나 값을 직접 확정하세요" 안내. 근거 문서가 갱신되면 이 스킬을 다시 돌려 PRD를 재조정한다. 한국어 + 마크다운, 식별자 영문.
