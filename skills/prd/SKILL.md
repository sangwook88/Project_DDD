# prd — 외부 공개용 PRD 저작 (Typst + 도식)

흩어진 기획 산출물(브리프·로드맵·HOME·ARCHITECTURE·FE 플로우)을 **하나의 외부 조망 문서**로 종합해 **Typst로 저작하고 PDF로 렌더**한다. 대상 독자 = 팀 외부(비개발자 포함) — 맥락 없이 읽어도 "무엇을 / 왜 / 누구를 위해"가 통해야 한다. 텍스트만 나열하면 구조·흐름이 안 잡히니 **핵심을 도식화**한다(타임라인·관계도·플로우·표). 내부 구현 상세·티켓 명세는 [ticket](../ticket/SKILL.md) 몫이라 여기선 **제품 가치로 번역**만 한다. 전제: 최소 브리프+로드맵(HOME·ARCHITECTURE·FE 플로우 있으면 풍부해짐) + **typst CLI**. 규약: [docs/conventions.md](${DDD_ROOT}/docs/conventions.md). 템플릿: [templates/prd.typ](${DDD_ROOT}/templates/prd.typ). 산출: `docs/PRD.typ` (+ `docs/PRD.pdf`).

## 이 스킬이 답하는 것
- **무엇을** — 제품 한 줄 요약 + 해결하는 문제.
- **누구를 위해** — 타깃 사용자·페르소나.
- **왜 이게 좋은가** — 핵심 가치·차별점.
- **뭐가 되나 / 안 되나** — 주요 기능(범위 In/Out) + 기능 관계도.
- **어떻게 쓰나** — 핵심 사용자 흐름(플로우 도식).
- **어디로 가나** — 로드맵 요약(버전 타임라인) + 성공 지표(있으면).

## 절대 규칙
1. **AI는 값을 짓지 않는다.** 근거 문서에 없는 수치·페르소나·지표·차별점을 상상하지 않는다 — 빈 곳은 템플릿의 `slot("…")` 로 남겨 사람이 채운다(규약 계승).
2. **도식도 짓지 않는다.** 다이어그램은 근거(로드맵의 버전, HOME `## 참조 그래프`의 엣지, FE `플로우.md`의 단계)를 **시각화만** 한다 — 없는 버전·엣지·단계를 그리지 않는다. 근거가 없는 도식은 넣지 말고 해당 절을 슬롯으로 둔다.
3. **근거에 접지.** 모든 문장·도식은 브리프·로드맵·HOME·ARCHITECTURE·플로우의 실제 내용에서만 끌어온다. 근거 없는 주장(시장 규모·경쟁 우위 등)은 리서치 노트에 출처가 있을 때만, 없으면 슬롯.
4. **외부 언어로 번역.** 내부 도메인명·패턴(TS/DM)·모듈 경계·기술 스택 세부를 그대로 노출하지 않는다 — "무엇을 할 수 있는가"의 사용자 가치로 바꾼다(예: `be/payment 도메인` → "결제"). 도식 노드 라벨도 도메인명이 아니라 사용자 가치 표현으로. 스택은 필요할 때만 한 줄로.
5. **읽기 전용 위키.** 근거 문서·코드는 읽어 접지만, 쓰는 건 `docs/PRD.typ`(+렌더된 `docs/PRD.pdf`)뿐. 원본 기획 문서를 고치지 않는다.
6. **범위 = 현재 타깃 버전 중심.** "주요 기능(In)"은 로드맵의 현재 타깃 버전 포함 기능을, "Out/다음"은 이후 버전·YAGNI를 근거로 적는다. 타임라인은 현재 타깃 버전을 강조.

## 시작 전 읽기
1. `docs/brainstorming/*-brief.md` — **거시 목표**(문제·가치·대상·핵심 기능)의 1차 소스. 없으면 "무엇을 만드는 제품인지" 최소 근거가 없으니 [brainstorm](../brainstorm/SKILL.md) 먼저 안내.
2. `docs/roadmap.md` — 버전 스코프 표 + **현재 타깃 버전** → 주요 기능 In/Out·로드맵 타임라인·성공 지표의 근거.
3. `docs/HOME.md` — 도메인 지도 + `## 참조 그래프`(FE→BE 엣지) → 기능 관계도 도식의 근거이자, 실제 구현 범위를 기능 가치로 번역할 재료(도메인명은 그대로 쓰지 않음).
4. `docs/fe/*/플로우.md`(있으면) — FE 도메인 플로우 → **핵심 사용자 흐름** 도식의 근거. 대표 여정 1~2개만 뽑는다.
5. `docs/brainstorming/*-research.md`(있으면) — 시장·경쟁 근거 → 차별점·성공 지표의 **출처 달린** 뒷받침.
6. `docs/arch/ARCHITECTURE.md`(있으면) — 스택 한 줄 요약이 필요할 때만 참고.
7. `templates/prd.typ` — 저작 골격(프리앰블·목차·도식 스캐폴드·slot 헬퍼). 이걸 근거로 채운다.
8. `docs/PRD.typ` — 이미 있으면 *갱신*(근거 문서 변화분 반영). 없으면 템플릿에서 새로 만든다.

## 흐름
1. **typst 확인** — `typst --version` 로 CLI 존재를 확인한다. 없으면 **멈추고** 설치를 안내한다(`https://github.com/typst/typst` — winget: `winget install --id Typst.Typst`, 또는 cargo/스크립트). typst는 이 산출의 필수 전제다.
2. **근거 수집** — 위 문서를 읽어 목차별·도식별 재료를 모은다. 브리프가 없으면 멈추고 brainstorm으로 되돌린다.
3. **번역 초안** — 각 목차 칸을 근거→외부 언어로 채운다. 도식은 근거의 버전/엣지/단계를 노드·엣지로 옮긴다(라벨은 사용자 가치로). 근거가 없는 칸·도식은 짓지 말고 `slot("…")`.
4. **슬롯·모순 점검** — 비었거나(성공 지표가 흔함) 문서 간 어긋나는 곳을 목록으로 사람에게 확인.
5. **PRD 저작** — 확인 뒤 `templates/prd.typ`를 골격으로 `docs/PRD.typ`를 덮어쓴다. 남은 슬롯은 그대로 둔다(거짓보다 빈칸).
6. **렌더** — `typst compile docs/PRD.typ docs/PRD.pdf`. 첫 컴파일 때 도식 패키지(fletcher 등)를 typst universe에서 내려받는다(네트워크 필요). 에러가 나면 고쳐 다시 컴파일해 PDF가 나오는 것까지 확인한다.

## 산출 — docs/PRD.typ (→ docs/PRD.pdf)
[templates/prd.typ](${DDD_ROOT}/templates/prd.typ)의 골격을 채운 Typst 문서 한 장. 고정 목차 + 도식 4종, 제품 가치 중심 톤:

- **표지** — 제품명(한국어) + 한 줄 요약.
- **해결하는 문제 / 타깃·페르소나 / 핵심 가치·차별점** — 텍스트(근거 없으면 `slot`).
- **주요 기능** — 범위 In/Out `#table` + **기능 관계도**(HOME 참조 그래프를 `fletcher` 노드-엣지로, 라벨은 사용자 가치).
- **핵심 사용자 흐름** — FE 플로우를 `fletcher` 플로우차트로(대표 여정 1~2개).
- **성공 지표** — 근거 있으면 `#table`, 없으면 `slot`(짓지 않는다).
- **로드맵 요약** — **버전 타임라인**(`fletcher`, 현재 타깃 버전 강조) + 버전 표.

규약:
- 도식 패키지는 템플릿이 고정한 버전(`@preview/fletcher:0.5.8`)을 쓴다 — 버전을 임의로 바꾸지 않는다.
- 한글 폰트는 프리앰블의 폴백(`Malgun Gothic`)을 따른다. 환경 폰트가 다르면 그 한 줄만 바꾼다.
- 제품명·설명은 한국어, 식별자·버전 라벨은 영문/원표기.
- 내부 도메인명을 노출하지 않는다 — 로드맵/HOME/플로우의 기능·엣지·단계를 사용자 가치 문장·라벨로 바꿔 적는다.
- 산출 위치는 위키 루트 직접 `docs/PRD.typ`(단일 조망 문서, roadmap.md와 같은 층), 렌더물은 `docs/PRD.pdf`.

## 종료
저작한 `docs/PRD.typ` + 렌더된 `docs/PRD.pdf` 경로, 그리고 남은 `slot(…)` 슬롯 목록(특히 성공 지표·페르소나·차별점 근거, 근거 없어 비운 도식)을 요약해 제시한다. "슬롯을 채우려면 brainstorm/roadmap으로 되돌리거나 값을 직접 확정하세요" 안내. typst가 없어 렌더를 못 했으면 `.typ`까지만 남기고 설치 후 `typst compile docs/PRD.typ docs/PRD.pdf` 를 안내한다. 근거 문서가 갱신되면 이 스킬을 다시 돌려 PRD를 재조정·재렌더한다.
