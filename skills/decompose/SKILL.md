# decompose — FE/BE 도메인 분할 확정 (기획 전단 2단계)

기능을 **FE 도메인**과 **BE 도메인**으로 가른다. 한 도메인이 둘을 다 짊어지지 않는다(수직 도메인 금지). AI가 제안하고 **사람이 확정**한다. 전제: [roadmap](../roadmap/SKILL.md)이 자른 **현재 타깃 버전** 범위(있으면) + [brainstorm](../brainstorm/SKILL.md) 설계 브리프(또는 막연한 아이디어). 규약: [docs/conventions.md](${DDD_ROOT}/docs/conventions.md). 산출: `docs/HOME.md`.

## 절대 규칙
1. **값 생성 금지.** 수치·규칙·계산식을 짓지 않는다. 도메인 *경계와 책임*만 가른다.
2. **한 번에 한 갈림길.** 도메인 하나씩 제안 → 확정.
3. **2분할 경계.** 흐름·화면·전환 = FE / 무슨 데이터·무슨 계산 = BE. 한 기능은 보통 FE+BE 둘로 쪼개진다.
4. **참조 단방향.** FE → BE(링크 호출), BE는 FE를 모른다. BE→BE 의존도 단방향·비순환.
5. **기능/관심사별 세분할.** 기능·관심사별로 잘게 가른다(HOME=위키 해부도). **반사적 merge(하나로) 추천 금지**. (규약 [§분할 granularity](${DDD_ROOT}/docs/conventions.md))

## 시작 전 읽기
1. `docs/roadmap.md` — 있으면 **현재 타깃 버전**과 그 버전 *포함 기능*만 분할 대상으로 삼는다(범위 밖 기능은 다음 버전 슬롯 — 도메인으로 가르지 않는다). 없으면 기능 전체가 대상.
2. brainstorm 설계 브리프(`docs/brainstorming/*-brief.md`) — 있으면 입력으로.
3. `docs/HOME.md` — 기존 도메인 지형(있으면). 없으면 새로 만든다.
4. `docs/CONTEXT.md` — 용어·공유 개념(있으면).
5. 코드 현황(가볍게) — 기존 디렉토리·모듈로 이미 선 그어진 경계 파악.

## 흐름
1. **입력 수집** — 브리프/아이디어/문서 경로. 비었으면 "무엇을 만들고 싶으신가요".
2. **맥락 살짝** — HOME·CONTEXT로 기존 도메인·용어, 중복·소속 판단.
3. **FE/BE 분할 초안 + 확정** — 기능/관심사별로 잘게 가른 FE·BE 후보 초안을 **하나씩** 확인:
   - FE 후보: 잠정 slug(`fe/<영문>`) · 한 줄 역할(어떤 플로우) · 신규 vs 기존.
   - BE 후보: 잠정 slug(`be/<영문>`) · 한 줄 역할(무슨 데이터·기능) · 신규 vs 기존. **기획은 FE-first이므로 BE 경계는 여기서 못박지 말고 잠정(provisional)으로 둔다** — plan-fe가 FE 호출을 드러낸 뒤 도출·확정/병합한다. FE 플로우가 아직 막연하면 BE 분할을 plan-fe 이후로 미뤄도 된다.
   - 한 기능이 FE·BE 어디 속하는지 애매하면 성분(흐름/계산)으로 갈라 묻는다.
   - **분할 기준**: "책임이 다른가"가 아니라 **"각자 자기 데이터/관심사를 소유하는가"**. 얇아도 별개 관심사(예: HITL 검토)면 분리 정당 — 단 공유 필드는 소유자 1개 + 단방향 참조. **의심스러우면 가른다**(반사적 merge 금지).
4. **참조·의존 짚기** — FE→BE 호출과 BE 간 의존을 단방향으로 정리. 순환이 보이면 경계 재검토.
5. **중복·충돌 점검** — 기존 도메인과 책임이 겹치면 흡수/분리 중 사람이 결정.

## 산출 — docs/HOME.md
도메인 지도를 갱신(없으면 생성):
```markdown
# 도메인 지도

## FE 도메인
| slug | 역할(한 줄) | 상태 |
|---|---|---|
| fe/<name> | … | not-started |

## BE 도메인
| slug | 역할(한 줄) | 상태 |
|---|---|---|
| be/<name> | … | not-started |

## 참조 그래프
- fe/<A> → be/<B>     # FE A가 BE B의 기능을 호출 (단방향)
- be/<B> → be/<C>     # BE 간 의존 (단방향)
```
- slug는 영문(`fe/`/`be/` 트랙), 역할은 한국어 한 줄.
- 참조 그래프는 뒤(arch·ticket)에서 패턴 배치·티켓 순서의 근거.

## 종료
확정 FE 도메인 수 + 잠정 BE + 참조 요약 + "다음 = [plan-fe](../plan-fe/SKILL.md)로 FE 플로우 먼저 구체화 → 거기서 도출한 BE를 [plan-be](../plan-be/SKILL.md)로 명세(FE-first)" 안내. 한국어 + 마크다운, 식별자 영문.
