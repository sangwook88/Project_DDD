# intake — raw 문서 접수 진입점 (비서)

`raw/` 인박스 문서(회의록·신규 기획·리팩토링 메모)를 **문서 1개당 브랜치 1개**로 갈라 [intake 에이전트](${DDD_HOME}/agents/intake.md)에 처리시키는 메인 스레드 안내데스크. 스킬은 **스캔·게이트·디스패치**만 하고 분류·구현은 에이전트가 한다. 규약: [docs/conventions.md](${DDD_ROOT}/docs/conventions.md).

## 절대 규칙
1. **분류·구현을 직접 하지 않는다.** 문서 판정·수정·티켓·코드는 전부 서브에이전트로 인계.
2. **값 생성 금지** — 산출물 직접 편집 안 함.
3. **사람이 게이트.** 어느 문서를 언제 처리할지, 2단계 구현으로 넘길지는 사람이 정한다. 자동 순회 안 함.
4. **push·merge 안 함.** 브랜치는 로컬에 남기고 머지는 사람이.

## 상태 스캔
- `raw/*.md` — 미처리 문서(아래 "처리 표시" 기준). 비었으면 "처리할 raw 문서가 없습니다".
- `git branch` 중 `intake/*` — 티켓 발행 후 **검수 대기**(2단계 구현 대기) 브랜치.
- `docs/HOME.md` — 문서가 닿을 기존 도메인 지형(참고).

## 모드 판정
| 상태 | 모드 | 동작 |
|---|---|---|
| 미처리 raw 문서 있음 | **접수(1단계)** | 문서 목록 제시 → 사람이 고름 → 문서마다 브랜치+intake 에이전트 디스패치 |
| `intake/*` 브랜치 검수 대기 | **구현(2단계)** | 사람이 검수 끝낸 브랜치를 골라 intake 에이전트를 **구현 모드**로 재트리거 |

## 접수(1단계) 디스패치
1. **목록·게이트** — 미처리 `raw/*.md`를 한 줄 요약으로 보여주고 처리 대상을 사람에게 확인(전체/일부).
2. **문서마다 격리 디스패치** — 고른 문서 각각에 `Agent`(subagent_type: `intake`, `isolation: "worktree"`)를 띄운다. 서로 독립이라 한 메시지에서 병렬 가능. 각 에이전트에 넘긴다:
   - 배정 raw 문서 경로 1개 + 모드 = 접수,
   - "규약 SoT = docs/arch/ARCHITECTURE.md", 경계 엄수·값 생성 금지.
   - worktree 브랜치는 `intake/<doc-slug>` 명명 권장(에이전트 커밋이 그 브랜치에 남음).
3. **처리 표시** — 에이전트가 접수를 마치면 그 문서를 처리됨으로 표시(아래).

## 구현(2단계) 디스패치
- 사람이 "브랜치 `intake/<slug>` 티켓 검수 끝, 구현해" 하면 그 브랜치로 `Agent`(subagent_type: `intake`, 모드 = 구현)를 띄워 확정 티켓을 dev로 구현시킨다. 끝나면 브랜치 커밋 + 보고. 머지는 사람.

## 처리 표시 (중복 접수 방지)
- 접수 끝난 문서는 `raw/_done/`로 이동(또는 front-matter에 `status: done` + `branch: intake/<slug>`). 재스캔 시 `raw/_done/`·`status: done` 제외.

## 인계 형식
"raw 문서 N개 중 <고른 것> → 문서당 `intake/<slug>` 브랜치로 처리합니다" 한 줄 + 각 문서의 예상 트랙(짐작)·넘길 입력 명시. 트랙 판정 자체는 에이전트가 한다. 한국어 + 마크다운, 식별자 영문.
