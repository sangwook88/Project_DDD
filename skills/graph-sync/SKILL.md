# graph-sync — 참조 그래프 재조정

CI(`home-check`)가 **HOME ↔ 선언(depends:/요소 링크) 불일치**로 막았을 때, 사람이 HOME을 손으로 고치는 대신 **선언에서 HOME `## 참조 그래프`를 결정적으로 재조정**한다. 규약: [docs/conventions.md](${DDD_ROOT}/docs/conventions.md) §연동 방식·§인터페이스.

## 무엇을 하나 (그리고 안 하나)
- **한다:** `depends:`/요소 `## 호출하는 기능`에서 유도한 엣지에 HOME을 **병합** — 빠진 엣지 추가, stale 엣지 제거. 살아남는 엣지의 `[event]`·주석은 **그대로 보존**(재생성 아님).
- **안 한다:** 생 코드에서 엣지를 *추론*하지 않는다(선언만 신뢰). 엣지를 *발명*하지 않는다 — dev가 이미 적은 선언을 HOME에 비출 뿐. **커밋·push 안 한다**(사람이 diff 검토 후).

## 절차
1. **재조정** — `node ${DDD_ROOT}/scripts/home-check.mjs --root ${DDD_ROOT}/docs --fix` 실행.
   - 출력의 `추가 N / 제거 M`을 사람에게 보고.
2. **새 엣지 연동방식 확인** — 자동 추가된 엣지는 `# 자동 추가 — 연동방식(sync/event) 확인` 주석이 달린다. 각 엣지가 **동기 호출(sync)** 인지 **이벤트 구독(event)** 인지 사람에게 물어, event면 엣지에 `[event]` 표기하고 주석 정리(규약 §연동 방식 — event는 구독자→발행자 방향).
3. **자동으로 못 고치는 문제 보고** — `--fix`는 엣지 드리프트만 해소한다. exit 1로 남는 것(코드 폴더 없음·표 누락·순환)은 **자동 수정 대상이 아니다**: 코드 위치는 `code:`/폴더로, 표 누락은 decompose로, 순환은 경계 재검토로 사람에게 돌린다.
4. **재검증** — `node ${DDD_ROOT}/scripts/home-check.mjs --root ${DDD_ROOT}/docs`가 ✓ 일치(exit 0)인지 확인.
5. **diff 검토 안내** — `git diff docs/HOME.md`를 사람이 검토하도록 안내. 새 엣지가 의도된 결합인지(경계 위반 아닌지) 여기서 사람이 최종 판단. **커밋은 사람이.**

## 경계
- HOME의 엣지 *집합*은 선언에서 파생되지만, 엣지 *메타데이터*(연동방식·주석·순서·도메인 표)는 사람 소유 — 스킬이 지우지 않는다.
- 새 도메인 경계가 필요한 상황(엣지가 아니라 경계 신설)이면 이 스킬이 아니라 decompose로. 값·연동방식을 **짓지 않는다**(묻는다).
